# 飞书多 Agent 群聊协作规约（权威版 v2 · 修正版）

> 2026-10-23 主人侧受控实验定论（4 条对照消息 + 历史消息 mentions 结构逐一核验）。
> **v1 作废**：v1 中「引用回复即可送达、正文可不写 @」是错误结论，已导致一次全员汇报丢失。
> 各成员立即用本版覆盖记忆中 v1 及一切自查归因。本文件是唯一权威口径。

---

## 核心规则（唯一需要记住的一句）

**要谁收到，就 @ 谁：正文必须原样包含对方在名单里的完整 `<at>` 标签。**

```
<at user_id="ou_xxxxxxxxxxxx">名字</at>
```

这是送达的**唯一通行证**。实证结论：
- 带真实 @ 标签的消息（纯文本或富文本均可）→ **100% 送达**
- 引用回复**不产生任何送达效果**（只是界面上的关联，方便对方知道你在回哪条）
- 不带 @ 的消息，无论是否引用回复 → 点名制下对方**收不到，且无任何提示**
- `@所有人`（`<at user_id="all"></at>`）→ 全员送达，用于广播

---

## 二、写作规范

1. **汇报/应答/派单**：正文第一处放对方的完整 `<at>` 标签，再写内容。
   建议同时「引用回复」对方的相关消息——不是为了送达，是为了让对方知道
   你在回应哪件事（上下文关联）。
2. **点名多人**：每个目标各一个标签，缺一不可。
3. **全员通知**：`<at user_id="all"></at>`。
4. **标签纪律（严格执行）**：
   - 从自己的 SOUL 名单（【飞书@格式】章节）**一字不差复制**标签
   - **不许**去掉 `user_id="ou_..."` 只写 `@名字`——纯文字 @ 没有任何送达效果
   - **不许**改写、转义（如把名字里的括号写成 `\(`）、拆分标签
   - 名单里没有的人（新成员等）：**不要猜 open_id**，报告主人补录
5. **汇报标准格式**（示例）：

```
<at user_id="ou_xxx">M总(sc)</at> [T-03] 已完成
- 结果：……
- 问题：……
（发送时同时引用回复 T-03 的派单消息）
```

---

## 三、禁止事项

1. **禁止 @ 语法实验**：不要尝试不同写法"造"@。机制已由主人受控实验定论，
   正确写法就是名单里的标签原样复制，不存在更好的写法。
2. **禁止自行发起通道测试**：通道验证是主人的事。
3. **禁止在纯文字 @ 后等待回应**：`@名字` 文字没有送达效果，会误判对方失联。
4. **禁止自行变更协作口径**：以本文件和主人为准。

---

## 四、问题处理协议（省 token 纪律）

**遇到任何通信/协作异常：报告一次，然后停手。**

1. 用一条消息向主人报告：`[通道异常] 现象、我最后一条消息的原文、时间`
2. 停止尝试，等待指示。不要换方法重试、不要发动其他成员排查、
   不要修改记忆结论、不要构造对照实验。

---

## 五、给总管的执行步骤

1. 用本文件覆盖自己记忆中的 v1 规约及一切通道结论
2. 发一条**含全员 @ 的消息**同步本版规则（引用本文件要点），要求每位成员
   引用回复"已更新 v2"
3. 检查各成员 SOUL 名单的 @ 标签是否完整（本轮 collect-ids 已回填，
   最近的群内点名消息可作为佐证）；发现占位符（ou_xxx）立即报告主人
4. 成员违规（纯文字 @ / 无 @ 汇报）：引用回复纠正一次；再犯报告主人

## 附：实证依据（主人侧受控实验，2026-10-23）

| 实验/样本 | 形态 | 结果 |
|---|---|---|
| 引用回复 M总 的消息，无 @ | text | **未送达** |
| 引用回复 + 正文 at 标签（text） | text | **送达**（mentions 出现实体） |
| 引用回复 + at 标签（post/md） | post | **送达** |
| 22:35/22:51 历史成功消息 | text/post | 均带真实 @ 实体（曾因接收方剥离而"看起来裸"） |
| 昨夜全员定时汇报（全部丢失） | post，mentions=0 | **未送达**——正文没写 @ 标签 |

结论：送达由 **@ 实体**唯一决定；引用回复、消息类型、markdown 均无送达作用。
